# Pincer 0.7.6 — Slack Native, MCP OAuth 2.0, and the Tools Catalog

**Release date:** 2026-04-19
**PyPI:** <https://pypi.org/project/pincer-agent/0.7.6/>
**Install:** `pip install -U pincer-agent`

---

## TL;DR

0.7.6 is a **capability + interoperability** release.

- **71 new Slack tools** — native bot/user-token surface covering messages, channels, users, files, reactions, pins, bookmarks, reminders, and search.
- **MCP OAuth 2.0** — Pincer can now expose its tools to remote MCP clients over a full OAuth 2.0 Authorization Server with PKCE, JWT, and scope-based access.
- **Google Workspace Meet v2** — 27 more tools; Google Workspace surface is now 113 tools.
- **Tools Catalog** — authoritative, searchable inventory of every tool Pincer can call: **304 native + unlimited MCP**.

No breaking changes. Upgrade is drop-in.

## What's new

### 1. Slack Native Integration — 71 tools

This is separate from Pincer's existing Slack *channel* (inbound messaging). The **native integration** is the tool surface Pincer exposes to the agent so it can act on Slack the way it already acts on Gmail or Google Calendar.

| Module | Count | What it covers |
|---|---|---|
| `tools_messages.py` | 18 | channel history, threads, post, schedule, Block Kit, DM, broadcast replies, summarize channel |
| `tools_channels.py` | 16 | list / create / archive / rename / set topic / set purpose / join / leave / invite / kick / open DM / open group DM |
| `tools_users.py` | 10 | list users, lookup by email, presence, user groups CRUD |
| `tools_files.py` | 10 | list / upload / download / share / delete + remote-file references |
| `tools_misc.py` | 12 | pins, bookmarks, reminders, search messages + files (user token) |
| `tools_reactions.py` | 5 | add / remove reactions, list emoji |

**Enable:**

```bash
pip install "pincer-agent[slack]"
export PINCER_SLACK_BOT_TOKEN=xoxb-...
export PINCER_SLACK_USER_TOKEN=xoxp-...    # optional, required only for search
```

Tools auto-register at startup when the bot token is present.

### 2. MCP OAuth 2.0 Authorization Server

Pincer ships a full OAuth 2.0 Authorization Server for its MCP endpoint under `src/pincer/mcp/auth/`.

- **Endpoints:** `/authorize`, `/token`, `/introspect`, `/revoke`
- **Discovery:** RFC 8414 server metadata
- **PKCE** for public clients
- **JWT** access tokens (PyJWT, RS256 by default)
- **Scopes** — read, write, destructive, admin (configurable)
- **Bearer-token middleware** wraps protected MCP routes
- **Client flow** also bundled — Pincer can consume OAuth-protected MCP servers too
- **Storage:** SQLite for clients/tokens; signing keys in OS keyring

This lets you plug Pincer into Claude Desktop, third-party MCP hosts, enterprise gateways, or your own agents — authenticated, scoped, revocable.

### 3. Google Workspace Meet v2 — 27 new tools (total 113)

Extends the Google Workspace surface with Meet v2 REST:

- **Spaces** — create / get / update / end / moderation / artifacts / members
- **Conference records** — list + participants + sessions
- **Recordings** — list / get / download / status
- **Transcripts** — list + entries + summarization
- **Smart notes**
- **Event subscriptions**

The previous Google Workspace count of **85** was undercounted; the catalog now correctly lists **113**.

## Upgrade

```bash
pip install -U pincer-agent
```

### Opt into the new surfaces

```bash
# Slack Native
pip install "pincer-agent[slack]"
export PINCER_SLACK_BOT_TOKEN=xoxb-...

# MCP (OAuth server/client both live here)
pip install "pincer-agent[mcp]"

# Or everything
pip install "pincer-agent[all]"
```

Then re-run:

```bash
pincer doctor    # verify env + new OAuth/Slack checks
pincer init      # optional; only if you want to reconfigure
```

No config migration is required. Existing `pincer.toml` files from 0.7.5 continue to work unchanged.

## Industry standards this release aligns with

- **Semantic Versioning 2.0.0** — this is a MINOR release (`0.7.5 → 0.7.6`): new functionality, fully backward compatible.
- **Keep a Changelog 1.1.0** — root `CHANGELOG.md` uses Added / Changed / Fixed / Security sections per release.
- **RFC 6749 — OAuth 2.0 Authorization Framework** — `authorization_code` + `client_credentials` grants implemented.
- **RFC 7636 — PKCE** — required for public clients.
- **RFC 7662 — OAuth 2.0 Token Introspection** — `/introspect` endpoint.
- **RFC 7009 — OAuth 2.0 Token Revocation** — `/revoke` endpoint.
- **RFC 8414 — OAuth 2.0 Authorization Server Metadata** — discovery endpoint.
- **RFC 7519 — JSON Web Token (JWT)** — access token format.
- **Model Context Protocol 1.8** — full client + server compliance; resources, prompts, sampling, tools.
- **SLSA-style auditability** — every tool call is recorded in the Pincer audit log; MCP OAuth events included.
